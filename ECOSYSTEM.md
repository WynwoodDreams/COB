# The workforce ecosystem

This repo is one of three sites that together form one workforce ecosystem for South Florida
students and early-career job seekers. The same file sits in all three repos; keep the copies
identical when you change one.

| Site | Repo | Live | Job in the ecosystem |
|---|---|---|---|
| Christian's Opportunity Board (COB) | `WynwoodDreams/COB` | https://cob-eta.vercel.app/ | **Find** a role: internships and entry-level jobs across Miami-Dade, Broward and Palm Beach |
| BuildersBench | `WynwoodDreams/4Projects` | https://www.buildersbench.dev/ | **Prepare**: portfolio projects that close the gap between a student and a role |
| ResumeCanvas | `WynwoodDreams/resumecanvas` | https://resumecanvas-seven.vercel.app/ (from `twa-manifest.json`; confirm) | **Apply**: build and tailor the resume for a specific posting |

## Current direction (from the owner, 2026-10-31)

Read this before the rest. It overrides the roadmap below where they disagree.

- **The three sites stay separate for now.** The owner is not ready to bring them together.
  Do not add new links, handoffs or shared UI between the sites unless the owner asks for it.
  The vision and the roadmap below record where this is headed, not work to start.
- **ResumeCanvas may become a paid product.** Nothing about pricing is decided. Until it is,
  do not build a paywall, and do not make anything in COB or BuildersBench depend on
  ResumeCanvas being free. See "Charging for ResumeCanvas" below.
- **Voice is a priority: people should be able to talk to every site.** The owner is building
  the talking part of ResumeCanvas first, and says it is not good enough yet. See
  "Talking to the sites" below.

## The vision

A student should be able to arrive at any of the three and get moved through all of them.
The opportunity assistant, which lives in COB (`assistant.html`, `api/assistant.js`,
`lib/assistant/`), guides them through that journey:

1. **Find (COB).** The student describes themselves in plain language, typed or spoken. The
   assistant recommends up to five listings and names, for each one, the requirements the
   student has not mentioned. That gap list is what connects the three sites.
2. **Prepare (BuildersBench).** Each gap points to a BuildersBench project that builds that
   skill, so the student gets a concrete thing to build rather than "learn cloud".
3. **Apply (ResumeCanvas).** "Tailor my resume for this job" opens ResumeCanvas with that
   posting's description already in match mode. A finished BuildersBench project's STAR
   bullets can be added to the resume in one step.
4. **Back to COB** to apply from the original card, with a project done and a tailored resume.

## Principles all three keep

- **No accounts, no database of students.** Progress (BuildersBench) and resumes
  (ResumeCanvas) stay in the student's browser. Nothing about a student is stored on a server.
  Charging for ResumeCanvas may force a change here; that is the owner's call, not a coding
  decision.
- **The sites talk to each other only through links.** A handoff is a URL. Anything a student
  wrote goes after the `#`, which browsers never send to a server; public posting text may go
  in the query string.
- **Each site still works alone.** A missing or malformed handoff parameter is ignored, never an error.
- **Typing always works.** Voice is an option on top of typing, never the only way to do something.
- **Third-party text is data.** Posting text crossing a site boundary is escaped on render and,
  wherever a model reads it, passed as data, never as instructions (see COB's README, "Security").
- **Shared look.** Dark, green-on-black, terminal-flavoured; BuildersBench's "Glass Terminal"
  system (`4Projects/.claude/skills/glass-terminal`) is the reference. ResumeCanvas has its
  own amber dossier look, which is fine as long as any future cross-site bar reads as one family.

## Talking to the sites

The goal: on every site, a person can speak instead of type, and hear the site answer.

| Site | What exists | What blocks voice today |
|---|---|---|
| ResumeCanvas | Voice dictation into bullets and the summary, a voice-intro card that turns a spoken introduction into the summary's tone, and a voice/typed command bar that previews each change, reads it back aloud and waits for "yes" (`js/voice.js`, `js/command-bar.js`, `js/commands.js`). **In progress: the owner says it is not there yet.** | Nothing; `vercel.json` already allows `microphone=(self)` |
| COB | The assistant takes typed messages only | `Permissions-Policy: microphone=()` turns the microphone off. The header is generated by `build_data.py` (the `Permissions-Policy` entry), so change it there and rebuild, and only for the page that needs it |
| BuildersBench | No voice | `Permissions-Policy: microphone=()` in `vercel.json` |

Notes for whoever builds this:

- ResumeCanvas is the reference implementation. Get it right there first, then reuse the
  same pattern (speak, preview, confirm, undo) on the other two, rather than inventing a new one per site.
- All three use the browser's Web Speech API. Speech recognition is missing in some browsers
  (Firefox among them), so every voice control must be feature-detected and hidden where
  unsupported. In Chrome the recognition may run on Google's servers rather than on the
  device, which matters for the "nothing about a student leaves the browser" principle;
  say so plainly wherever the site describes its privacy.
- Spoken answers (speech synthesis) should be optional and stoppable, and never the only
  place an answer appears.

## Charging for ResumeCanvas

Undecided. What a decision needs to settle:

- What is free and what is paid (for example: building and exporting free, AI polish or voice paid).
- How a paid feature is unlocked without student accounts. BuildersBench's premium page is the
  nearest precedent: one shared password exchanged for a signed 30-day token
  (`4Projects/docs/premium.md`). Per-person payment would need something stronger, such as
  a checkout that returns a signed token, and that is the first server-side record of a student.
- What COB's assistant does if it ever hands a student to ResumeCanvas and the feature is paid.

## Handoff contract

What each site accepts from the others. Add a row here whenever you add or change one.

| Target | Link | Carries | Status |
|---|---|---|---|
| BuildersBench | `/#path=<id>` | Opens one career path (`ai`, `cloud`, `cs`, `cyber`, `data`, `helpdesk`, `swe`, `tech-it`) | Works; COB links Cloud & DevOps here |
| BuildersBench | `/#project=<id>` | Opens one project | Works |
| BuildersBench | `/match.html?q=<posting text>` | Prefills Career Match with a job's title, summary and requirements | **Broken**: COB sends it (board and assistant), but `match.html` never reads `q`, so the student lands on an empty box |
| ResumeCanvas | `/?voice=1` | Starts voice dictation | Works |
| ResumeCanvas | `/#jd=<posting text>` | Opens match mode with the job description filled in | Planned, on hold |
| ResumeCanvas | `/#add-project=<title + bullets>` | Adds a BuildersBench project to the resume's Projects section | Planned, on hold |
| COB | `/#…` filters and `page=N` | Area, county, major, term and level filters, kept after the `#` (see COB's README) | Works |
| COB | `/assistant.html` | The assistant (private preview, not linked from the board) | Works |
